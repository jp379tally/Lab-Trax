### Replit Build Brief

**Objective**
Fix doctor merging so case-only / capitalization-only duplicates like `Dr. Ray montalvo` and `Dr. Ray Montalvo` can be merged/canonicalized from Customer Center.

**User-visible problem**
In the merge modal, both Ray Montalvo rows show as `Target ✓`, `SOURCES (0)` remains empty, and the `Merge` button stays disabled. The user cannot add either spelling as a source.

**Likely root cause**
The frontend merge dialog collapses doctor row identity with `doctorName.toLowerCase() + providerOrganizationId`. That makes `Dr. Ray montalvo` and `Dr. Ray Montalvo` look like the same row. Separately, the backend rejects source/target pairs as “same” using case-insensitive name comparison, so even if the UI allowed selection, the API likely blocks pure casing merges.

* `artifacts/labtrax-desktop/src/pages/accounts.tsx`

  * Customer Center imports and uses `MergeDialog` from `@/pages/doctors`.
* `artifacts/labtrax-desktop/src/pages/doctors.tsx`

  * `MergeDialog`
  * source/target key generation
  * `sourceKeys`
  * `isTarget`
  * `targetSelfMerge`
  * initial source/target auto-pick logic
* `artifacts/api-server/src/routes/doctors.ts`

  * `loadAndAuthorizeMerge`
  * `normalizeKey`
  * self-merge rejection
  * source dedupe logic
  * `/merge/preview` and `/merge`

1. Add a frontend helper for exact merge row identity, preserving visible doctor-name casing:

   * `doctorRowKey(name, providerId) => `${name.trim()}|${providerId ?? ""}``
2. Use that exact key in `MergeDialog` for:

   * `sourceKeys`
   * `addSource`
   * search-result `inSources`
   * search-result `isTarget`
3. Change `targetSelfMerge` to reject only exact same trimmed doctor name plus same provider, not case-insensitive same name.
4. Ensure the dialog can represent this valid intent:

   * source: `Dr. Ray montalvo`

5. Update backend doctor merge validation:

   * continue rejecting exact same source and target
   * allow same provider + same name after lowercasing when the raw trimmed casing differs
6. Keep the actual case update case-insensitive so all casing variants under that provider are normalized to the chosen target spelling.
7. Add tests for capitalization-only duplicates.

### Debug Analysis

The strongest evidence is the screenshot: both `Dr. Ray montalvo` and `Dr. Ray Montalvo` are shown as target rows, and neither can be added as a source. The code supports that: `MergeDialog` computes keys with lowercased doctor names, so capitalization-only variants collapse.

The backend has a matching problem: `loadAndAuthorizeMerge` treats source and target as the same if their lowercase names and provider IDs match. That is correct for true duplicate clicks, but too strict for a casing cleanup where the target spelling is intentionally different.

Best fix is to treat UI row identity as exact-cased, while keeping backend data matching case-insensitive for the actual normalization. Confidence is high.
