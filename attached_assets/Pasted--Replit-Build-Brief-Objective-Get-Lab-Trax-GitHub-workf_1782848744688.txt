### Debug Analysis

The strongest evidence points to CI/release configuration, not a single LabTracks feature. Recent commits already fixed `secrets` usage in workflow `if:` expressions, pinned pnpm, changed release automation to manual-only, bumped `expo-av` for Expo SDK 54, and added `@react-navigation/native` to the mobile package.

The remaining risky spots are secrets and dependency drift. If GitHub still shows failures after the latest commit, the first thing to inspect is the exact failed step. A red `pnpm install --frozen-lockfile` means dependency/lockfile mismatch. A red Expo drift check means another mobile Expo package needs a stable SDK-compatible bump. A red storage integration test with auth errors means `CI_GOOGLE_CREDENTIALS_JSON` or the related CI storage secrets need refreshing.

The safest approach is targeted: preserve the tests and guards, fix only the exact failed class, and rerun the workflows on latest `main`. I would not remove the GCS tests, signing checks, or pnpm release-age policy.
