### Replit Build Brief

**Objective**
Fix the customer/doctor directory mismatch so any doctor name that appears in the new-case drop-zone doctor selector can also be found, reviewed, merged, or cleaned up from Customer Center.

**User-visible problem**
`Dr. Lauren Petral` appears in the Dashboard drop-zone doctor dropdown when adding a new case, but searching `petral` in Customer Center returns no practice/doctor rows. The correct doctor, `Dr. Pettis`, does appear. This prevents the lab from merging or deleting the bad spelling.

**Likely root cause**
The two screens are not using the same doctor source:

* Dashboard drop zone uses `GET /cases/doctor-names` in `artifacts/labtrax-desktop/src/components/DashboardDropZone.tsx`.
* That endpoint includes doctor names from both canonical `cases` and legacy/mobile `lab_cases` JSON blobs in `artifacts/api-server/src/routes/cases.ts`.
* Customer Center builds doctor rows from `GET /cases` plus practice/org data in `artifacts/labtrax-desktop/src/pages/accounts.tsx`.
* Legacy/mobile case rows are projected with `providerOrganizationId: null`, so a doctor name like `Petral` can exist in the autocomplete list but not attach to any visible practice row in Customer Center.

**Exact areas to inspect/change**

* `artifacts/api-server/src/routes/cases.ts`

  * `GET /cases/doctor-names`
  * `GET /cases/doctor-directory`
  * `GET /cases`
  * doctor merge route, especially legacy `lab_cases` rewrite behavior
* `artifacts/labtrax-desktop/src/components/DashboardDropZone.tsx`

  * `doctorNamesQuery`
  * `doctorDirectoryQuery`
  * `DoctorNamePicker`
* `artifacts/labtrax-desktop/src/pages/accounts.tsx`

  * `doctorRows`
  * `doctorsByPractice`
  * Customer Center search/filter logic
  * merge dialog source construction
* `artifacts/labtrax-desktop/src/pages/doctors.tsx`

  * existing `MergeDialog` / doctor merge source model

**Implementation plan**

1. Add a shared doctor-directory endpoint or enhance the existing one so it returns every doctor name visible to intake, with metadata:

   * doctor name
   * normalized name
   * provider organization ID when known
   * lab organization ID
   * source: canonical case, legacy/mobile case, registered doctor, unassigned doctor
   * case counts
   * whether it is mergeable/actionable

2. Update Customer Center so search checks this unified doctor directory, not only practice-attached canonical case rows.

3. For legacy-only or providerless names like `Dr. Lauren Petral`, show them under a clear row such as `Unassigned / legacy doctor names` or attach them to the best-known practice when the match is safe.

4. Make the merge flow accept legacy/providerless doctor-name sources, then call the existing doctor merge logic that rewrites both canonical cases and legacy `lab_cases` JSON doctor names.

5. After merging `Petral` into `Pettis`, invalidate/refetch:

   * `["case-doctor-names"]`
   * `["cases"]`
   * `["organizations"]`
   * invoices if doctor-name matching affects invoice selection

6. Optionally tighten the drop-zone picker so it does not show stale legacy-only names without context. If kept, mark them as legacy/unassigned so users know they need cleanup.

**Constraints and guardrails**

* Do not delete historical cases.

### Debug Analysis

**Primary root-cause hypothesis**
`Petral` is probably a legacy/mobile or providerless doctor-name string coming from `lab_cases.caseData.doctorName`. The drop-zone doctor picker includes those names through `/cases/doctor-names`, but Customer Center only renders doctors that can be grouped under visible practices from case/provider data. Since the bad name has no usable provider/practice row, Customer Center search cannot find it.

**Supporting evidence**

* Screenshot 1 shows `Dr. Lauren Petral` in the Dashboard drop-zone doctor dropdown.
* Screenshot 2 shows Customer Center search for `petral` returns zero matches.
* Current `DashboardDropZone.tsx` uses `/cases/doctor-names`.
* Current `/cases/doctor-names` reads both canonical `cases.doctorName` and legacy `lab_cases.caseData.doctorName`.
* Current `accounts.tsx` builds Customer Center doctor rows from `GET /cases`, then groups by `providerOrganizationId`; providerless legacy rows do not naturally land under a practice.
* `/cases/doctor-directory` explicitly excludes legacy `lab_cases` because they lack `providerOrganizationId`.

**Alternate hypotheses worth checking**

* `Petral` may be in an unassigned-doctors holding table and excluded from Customer Center practice rows.
* `Petral` may be archived/deleted or linked only to closed/no-open cases, though the screenshot suggests even the Customer Center search finds nothing.
* There may be a cache invalidation issue after a prior merge, but the persistent dropdown appearance points more strongly to a source mismatch.

**Why this fix is best**
The correct fix is not only to remove `Petral` from the dropdown. The lab needs an admin-visible cleanup path for every doctor string that can affect intake, pricing, search, or case history. A unified doctor directory/cleanup surface fixes both the symptom and the data governance problem.

**Confidence level**
High on the source mismatch. Medium-high on `Petral` specifically being legacy/providerless until Replit checks the live database row.
