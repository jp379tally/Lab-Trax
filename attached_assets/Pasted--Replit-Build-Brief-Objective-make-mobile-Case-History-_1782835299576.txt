**Debug Analysis**

The app surface is the mobile case detail screen, especially the Notes and History tabs. Notes are added through `useAddCaseNote()` with `{ noteText, visibility }`, and the Notes tab already renders `notes[].noteText`. History, however, renders `events[]` only.

The strongest evidence is in `artifacts/labtrax/app/case/[id].tsx`: `HistorySection` displays `eventDescription(ev)`, and `eventDescription()` only returns text for status changes or metadata fields named `note`/`message`. The API schema confirms the note input field is `noteText`. The database schema confirms note content lives in `case_notes.note_text`, while `case_events.metadata_json` is separate.

Primary hypothesis: the note event is present, but its note body is either stored as `noteText` or stored only as a note id/visibility in event metadata, and the mobile History renderer does not resolve it.

Alternate hypotheses:

* The server creates `note_added` events without any note id, making frontend resolution impossible without a server patch.
* The server filters `notes[]` correctly but not `events[]`, so blindly putting note text in event metadata could create a privacy leak for internal notes.
* Mobile print history has the same description gap because it mirrors the same limited metadata parsing.

Confidence: high that this is a mobile history rendering/data-contract gap, medium on the exact event metadata key until Replit inspects the live route.
