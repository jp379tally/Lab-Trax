### Debug Analysis

**Probable root cause**
The file-source chooser is implemented with `Alert.alert` inside `FilesSection.openAddSheet()`. That is the likely regression point. The reported “only the last four letters of photo show in the top-left” sounds like a native/web picker or action control being injected in the wrong place, not like an upload API failure.

**Supporting evidence**

* The broken behavior occurs immediately after tapping **Add photo or file**.
* The user cannot even select a photo, so upload/registration likely has not started.
* The repo shows picker launcher code in `artifacts/labtrax/app/case/[id].tsx`.
* The upload pipeline in `uploadCaseAttachment.ts` is separate and only runs after a file URI is selected.
* Existing tests cover opening/deleting attachments, but I did not see coverage for pressing **Add photo or file** and choosing camera/library/document.
* Regression guardrails explicitly protect mobile Files / photos / documents.

**Alternate hypotheses worth checking**

* An Expo `expo-image-picker` behavior changed after dependency/build changes.
* The app is being used through a mobile web/PWA surface where browser file-input behavior differs from native TestFlight.
* A global style/layout change is affecting modals, alerts, or picker overlays.
* Camera/photo permissions are denied, but that would normally show a permission alert, not a clipped top-left “photo” fragment.

**Why this fix is best**
Replacing the fragile alert chooser with an app-owned modal fixes the visible broken UI without touching storage, auth, or attachment APIs. It is low blast-radius, testable, and directly targets the point where the user gets stuck.

**Confidence level**
Medium-high. I could inspect the relevant mobile screen and upload pipeline, but I did not have a screenshot or live device reproduction. The symptom and code path line up strongly.
