### Replit Build Brief

**Objective**
Restore the LabTrax desktop download so clicking the Windows desktop download successfully downloads an available installer/package instead of Chrome showing `LabTrax-Setup.exe - File wasn't available on site`.

The browser starts a download for `LabTrax-Setup.exe`, then fails immediately with “File wasn’t available on site.”

**Likely root cause**
The app is pointing users to `/downloads/LabTrax-Setup.exe`, but the `LabTrax-Setup.exe` object is missing from App Storage or was never published after the latest Windows build.

Repo evidence:

* `artifacts/api-server/src/app.ts` serves `/downloads/LabTrax-Setup.exe` from App Storage as installer kind `exe`.

* `artifacts/labtrax-desktop/scripts/electron-build.mjs` notes that Linux/Replit builds may only create `LabTrax-Windows-Portable.zip` if NSIS/Wine cannot produce the `.exe`.
* `.github/workflows/build-windows.yml` and `.github/workflows/release.yml` publish `LabTrax-Setup.exe` only if the Windows build succeeds and `PLATFORM_ADMIN_SECRET` plus `PUBLISH_API_BASE_URL` are configured.

**Exact areas to inspect/change**

* `artifacts/api-server/src/app.ts`
* `artifacts/api-server/src/lib/desktop-installer-storage.ts`
* `.github/workflows/build-windows.yml`
* `.github/workflows/release.yml`
* Any desktop download UI/settings code that stores or renders the download URL. Search for:

  * `/downloads/LabTrax-Setup.exe`
  * `desktop-installer`
  * `downloadUrl`
  * `LabTrax-Windows-Portable.zip`

* Do not rename the installer casually. The server and workflow expect `LabTrax-Setup.exe`.
* Do not rely on a Replit/Linux build to produce the NSIS `.exe`; use `windows-latest`.
* Do not mask missing installer storage as success. A missing installer should be visible to admins.

### Debug Analysis

**Probable root cause**
The app is sending users to a valid route with an invalid/missing backing file. The route exists, but the App Storage object for `LabTrax-Setup.exe` likely does not.

**Supporting evidence**

* Screenshot shows a browser-level download failure for `LabTrax-Setup.exe`, not an in-app validation error.
* Server code explicitly serves `/downloads/LabTrax-Setup.exe` from App Storage.
* Storage mapping expects `desktop-installer/LabTrax-Setup.exe`.
* The build script says Replit/Linux may create only `LabTrax-Windows-Portable.zip` when a true NSIS `.exe` build cannot complete.
* Workflows publish the EXE only when Windows build and publish secrets are correct.

**Alternate hypotheses**

* The EXE exists, but the direct GCS redirect URL is invalid or expired too early.
* `PRIVATE_OBJECT_DIR` or Replit Object Storage is misconfigured.
* The UI/admin settings still point to an older stale download URL.
* The publish endpoint failed after upload but before settings were updated.

**Why this fix is best**
The durable fix is not just changing the text on the button. The app needs to align the visible download option with real storage availability, and the release pipeline must reliably publish the artifact users are being asked to download.

**Confidence**
High that this is a missing/unpublished installer or stale download URL. I could not directly test the live URL from this container because outbound access to the Replit app was blocked, but the screenshot plus repo code point strongly at the storage/publish path.
