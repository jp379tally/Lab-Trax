### Replit Build Brief

**Objective**
Make the downloaded LabTrax Desktop app match the live web app in navigation order, settings behavior, logo/image rendering, auth/security state, database-backed data, and update behavior.

**User-visible problem**
The installed desktop version appears stale or divergent from the web version:

* Sidebar tabs/order do not match the web version.
* Lab logo thumbnail is broken in Admin Settings.
* Two-factor authentication shows “Not enabled” on desktop even though the web version should reflect the current account state.
* Republishing the web app does not appear to update the already-downloaded desktop app.
* The desktop app needs an update notification/install flow so users do not have to manually redownload every time.

**Likely root cause**
The desktop app is a separate Electron/Vite bundle, not a live mirror of the web app. A Replit web republish updates the hosted web app, but an already-installed desktop app only changes when:

1. the desktop bundle is rebuilt,
2. the desktop app version is bumped,
3. update artifacts are published,
4. the installed app can reach the update feed,
5. the renderer actually installs/relaunches into the new version.

The repo already has an Electron auto-updater path in `artifacts/labtrax-desktop/electron/main.cjs`, plus update IPC in `electron/preload.cjs`, and an `UpdateBanner` mounted in `AppLayout`. That means the intended system exists, but the installed desktop build may be older, pointed at the wrong update feed, missing the latest UI bundle, or not publishing fresh update metadata.

The broken lab logo and 2FA mismatch are likely caused by either a stale desktop bundle or desktop-specific API/auth/media handling. Images often break in Electron when the UI uses a normal `<img src>` against a protected media URL that requires bearer auth/cookies. Desktop requests must use bearer tokens or a signed/public image URL.

**Exact areas to inspect/change**

* `artifacts/labtrax-desktop/src/components/AppLayout.tsx`
* `artifacts/labtrax-desktop/src/pages/settings.tsx`
* `artifacts/labtrax-desktop/src/components/UpdateBanner.tsx`
* `artifacts/labtrax-desktop/src/components/AuthedMedia.tsx`
* `artifacts/labtrax-desktop/src/lib/api.ts`
* `artifacts/labtrax-desktop/electron/main.cjs`
* `artifacts/labtrax-desktop/electron/preload.cjs`
* desktop build/publish scripts, especially anything like `scripts/desktop-build-publish.sh`
* API routes for `/api/auth/me`, 2FA status, logo upload/media serving, and `/downloads/latest.yml`

**Implementation plan**

1. Confirm the installed desktop app version and compare it to `artifacts/labtrax-desktop/package.json`.
2. Confirm the desktop app can fetch update metadata from the production update feed, likely `/downloads/latest.yml`.
3. Make sure every desktop release increments the desktop version and republishes updater artifacts.
4. Add or fix a visible update status panel/button in the desktop UI if the banner is not reliably visible.
5. Make desktop navigation source match the web version exactly, ideally by sharing one nav definition or copying the same ordering contract.
6. Fix lab logo rendering by using authenticated image loading or server-returned signed/public logo URLs.
7. Fix 2FA status by making desktop read live account security state from the same API response or endpoint as web.
8. Add regression checks for desktop login, `/auth/me`, logo thumbnail, 2FA state, sidebar order, and update feed behavior.

**Guardrails**

* Do not fork desktop behavior away from web behavior unless it is truly desktop-only, such as local file backup or iTero polling.
* Do not rely on cookies for desktop API authentication; Electron uses bearer tokens from the desktop auth flow.
* Do not “fix” this by telling users to redownload forever. A one-time reinstall may be acceptable only if the currently installed build predates the updater or has a bad feed URL.
* Avoid database migrations unless the API truly lacks the needed 2FA/logo fields.

**Acceptance criteria**

* Desktop sidebar order exactly matches the current web app.
* Desktop Admin Settings shows the same available tabs/features as web, except intentional desktop-only additions.
* Lab logo thumbnail renders after login and after logo replacement.
* 2FA status matches the live account state after refresh/logout/login.
* Desktop update UI shows current version, latest version/status, and a clear install/relaunch action when an update is available.
* After publishing a new desktop build, an already-installed app detects it without downloading a fresh installer manually.

**Regression risks**

* Auth token refresh in desktop.
* Protected media/image downloads.
* Admin-only settings visibility.
* Update feed version mismatch.
* Service worker/PWA caching if the desktop web build is served under `/desktop/`.
* Accidentally changing web navigation while fixing desktop navigation.

### Debug Analysis

Primary hypothesis: this is desktop/web drift caused by a stale or separately packaged Electron bundle, plus at least one desktop-specific auth/media gap.

The screenshots strongly support that: the desktop UI shows old/different navigation and settings state, while the repo already contains a newer-looking desktop architecture with bearer-token API handling, update IPC, and an `UpdateBanner`. A web republish alone cannot update an installed Electron app unless the desktop build/update artifacts are also published and the installed app is capable of applying them.

The broken logo points to protected media being loaded in a desktop renderer. If the image URL requires cookies or auth headers, a plain image tag will fail from `app://labtrax`. The desktop must use authenticated fetch/blob rendering or a server-provided signed/public URL.

The 2FA mismatch could be stale local state, a missing field from `/auth/me`, or an old desktop settings panel that does not call the same security endpoint as web.

Confidence: medium-high. I inspected the screenshots and relevant repo package/code structure, but I did not have the running app, current web screenshot, or live API responses.
